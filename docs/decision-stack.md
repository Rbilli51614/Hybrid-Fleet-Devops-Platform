# Six-Layer Decision Stack

| Layer | Choice | Why chosen over alternatives |
|---|---|---|
| **Traffic** | Route 53 (private hosted zone) + ALB Ingress on EKS; Site-to-Site VPN linking cloud VPC to "on-prem" VPC | A Transit Gateway or Direct Connect would be the real-world choice at larger scale, but a Site-to-Site VPN demonstrates the same routing/segmentation skills at near-zero cost. ALB over NLB because the workloads are HTTP-based and ALB gives path-based routing for multiple services behind one ingress. |
| **Compute** | EKS + Karpenter for cloud-native workloads; kubeadm on persistent EC2 ASGs for the VM tier; ARC for self-hosted runners | Karpenter over Cluster Autoscaler because it's faster to scale and bin-packs better, which matters for bursty CI workloads. kubeadm over k3s or EKS Anywhere for the VM tier because it mirrors the actual operational burden of Nutanix NKP most closely — you own upgrades, CNI selection/config, and cluster init/join by hand; k3s bundles enough of that away (SQLite/embedded etcd, a baked-in CNI, one binary) that it would under-demonstrate the skill this tier exists to show. ARC over a static runner pool because it eliminates idle-runner cost and stale-runner drift. |
| **Data** | S3 + DynamoDB for Terraform state/locking; versioned module registry (git-tag based); Nexus on EC2 + EBS with S3 lifecycle-managed backups | An S3-backed or hosted private registry would be cleaner but adds overhead/paid dependency; a git-tag-pinned module source is free and demonstrates the same module-governance discipline. Nexus stays on a VM (not containerized) deliberately — this needs VM-based ops experience, and simulating that reality is more valuable than "solving" it with a managed alternative. |
| **Security** | IRSA for EKS workload IAM; SSM Session Manager (no SSH keys) for VM-tier access; Secrets Manager for GitHub App/runner registration credentials; OPA/Gatekeeper enforced identically on both clusters; security groups isolating the "on-prem" VPC | IRSA over static IAM keys because it removes long-lived credentials from pods entirely. SSM over SSH/bastion because it removes an entire attack surface (open port 22, key distribution) and gives full session audit logs for free. Enforcing OPA on *both* clusters, not just EKS, is the point: policy parity is what the diverse-infrastructure problem actually needs. |
| **Cost** | Spot via Karpenter for ephemeral CI runner nodes; on-demand/reserved for the persistent VM-tier ASG; S3 lifecycle rules (Standard → IA → Glacier) for Nexus backups and build artifacts; cost allocation tags per team | CI runner workloads are stateless and interruption-tolerant, so Spot is close to free upside with minimal risk — the single highest-leverage cost decision in the stack. The VM tier stays on-demand/reserved because a self-managed control plane isn't safely interruptible. Per-team cost tags map directly to the embedded-DevOps-partner model (you need to tell a team what *their* infrastructure costs). |
| **Monitoring** | Amazon Managed Prometheus + Grafana federated across both clusters; OpenTelemetry Collector as the common ingestion layer; CloudWatch for AWS-native resources; Alertmanager → PagerDuty/OpsGenie; runbooks as versioned markdown in-repo | OpenTelemetry over a vendor-specific agent because it's the vendor-neutral choice that lets you swap the backend later without re-instrumenting anything. Managed Prometheus over self-hosted Prometheus removes one more stateful VM-based system from your own on-call burden. |
