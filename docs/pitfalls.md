# Pitfalls If Decision-Layer Inputs Change

| Layer | Trigger (input change) | Pitfall | Solution |
|---|---|---|---|
| **Traffic** | Org expands to multi-region or multi-DC for DR | Site-to-Site VPN and single-region Route 53 routing become a single point of failure | Move to AWS Transit Gateway with multiple VPN/Direct Connect attachments, and Route 53 latency-based or failover routing across regions |
| **Compute** | Org fully migrates off on-prem VMs to cloud | The dual-tier (EKS + VM) architecture becomes unnecessary overhead; maintaining two K8s control planes for one workload type wastes engineering time | Consolidate to a single EKS multi-cluster fleet (or one cluster, multiple node groups) managed via Cluster API or Karpenter-only; decommission the VM tier and fold its policy/observability config into the EKS-only baseline |
| **Compute** | CI workload volume grows 5–10x (many more teams onboard) | ARC runner pods contend with app workloads for EKS cluster capacity, causing app deploys and CI jobs to compete for nodes | Move ARC runners to a dedicated Karpenter NodePool with taints/tolerations so runner scaling never starves app workloads; consider a separate CI-only EKS cluster if the numbers justify it |
| **Data** | Number of teams consuming the shared Terraform module registry grows past a handful | Version pinning drift: teams pin different module versions, module owner can't safely make breaking changes | Move to a real private Terraform Registry (Terraform Cloud/Enterprise or a self-hosted alternative) with enforced semantic versioning and a deprecation policy, rather than a git-tag convention |
| **Data** | Nexus artifact volume grows to the point single-VM storage is a bottleneck | Manual EBS resizing becomes a recurring on-call task; single point of failure for all builds org-wide | Migrate to Nexus HA cluster (or a managed alternative like CodeArtifact/JFrog Cloud) with S3-backed blob storage instead of local EBS |
| **Security** | Self-hosted runners need access to internal/sensitive networks (e.g. private DBs during integration tests) | Long-lived runner pods become a persistent lateral-movement risk if compromised via a malicious workflow or dependency | Switch ARC to ephemeral mode (one-job-per-pod, destroyed after use), scope runner network access via Kubernetes NetworkPolicy, and require signed/verified workflows for anything touching sensitive network segments |
| **Cost** | Spot interruption rate spikes during peak CI hours (common with certain instance families) | CI job queue backs up, developer-facing pipeline latency increases, teams lose trust in the platform | Configure Karpenter with a diversified instance type pool and a mixed on-demand/Spot NodePool with a defined on-demand floor for critical-path pipelines |
| **Monitoring** | Team count and workload count grow 10x | Prometheus federation hits cardinality/storage limits, dashboards slow down or drop data | Shard remote-write across multiple Amazon Managed Prometheus workspaces per business unit, or migrate to Grafana Mimir/Thanos for horizontally scalable long-term storage |
